# Тестовая документация функции `get_result`

## Назначение функции

Функция принимает два параметра:

- `score` — баллы студента от 0 до 100;
- `attendance` — посещаемость от 0 до 100.

Сначала проверяется тип каждого параметра, затем допустимый диапазон. После этого результат определяется по порогам баллов и посещаемости.

## Классы эквивалентности

### Параметр `score`

| Класс | Диапазон или тип | Ожидаемое поведение |
|---|---|---|
| 1 | меньше 0 | `Некорректный балл` |
| 2 | 0–49 | Допустимый балл, результат зависит от посещаемости |
| 3 | 50–69 | При посещаемости от 60: `Зачёт` |
| 4 | 70–89 | При посещаемости от 70: `Хорошо` |
| 5 | 90–100 | При посещаемости от 80: `Отлично` |
| 6 | больше 100 | `Некорректный балл` |
| 7 | неправильный тип | `TypeError` с сообщением `Баллы должны быть числом` |

### Параметр `attendance`

| Класс | Диапазон или тип | Ожидаемое поведение |
|---|---|---|
| 1 | меньше 0 | `Некорректная посещаемость` |
| 2 | 0–59 | Допустимая посещаемость, результат зависит от баллов |
| 3 | 60–69 | При баллах от 50: `Зачёт` |
| 4 | 70–79 | При баллах от 70: `Хорошо` |
| 5 | 80–100 | При баллах от 90: `Отлично` |
| 6 | больше 100 | `Некорректная посещаемость` |
| 7 | неправильный тип | `TypeError` с сообщением `Посещаемость должна быть числом` |

## Граничные значения

Проверяются значения непосредственно за пределами допустимого диапазона, его края и значения около порогов классификации:

- `score`: `-1`, `0`, `49`, `50`, `69`, `70`, `89`, `90`, `100`, `101`;
- `attendance`: `-1`, `0`, `59`, `60`, `69`, `70`, `79`, `80`, `100`, `101`.

## Таблица тест-кейсов

| ID | `score` | `attendance` | Тип проверки | Ожидаемый результат |
|---|---:|---:|---|---|
| TC-01 | 90 | 80 | Позитивный, нижняя граница «Отлично» | `Отлично` |
| TC-02 | 100 | 100 | Позитивный, максимальные значения | `Отлично` |
| TC-03 | 70 | 70 | Позитивный, нижняя граница «Хорошо» | `Хорошо` |
| TC-04 | 89 | 79 | Позитивный, верхняя граница «Хорошо» | `Хорошо` |
| TC-05 | 50 | 60 | Позитивный, нижняя граница «Зачёт» | `Зачёт` |
| TC-06 | 69 | 69 | Позитивный, верхняя граница «Зачёт» | `Зачёт` |
| TC-07 | 0 | 0 | Позитивный допустимый, минимальные значения | `Незачёт` |
| TC-08 | 49 | 59 | Позитивный допустимый, результат «Незачёт» | `Незачёт` |
| TC-09 | -1 | 80 | Негативный, балл меньше 0 | `Некорректный балл` |
| TC-10 | 101 | 80 | Негативный, балл больше 100 | `Некорректный балл` |
| TC-11 | 90 | -1 | Негативный, посещаемость меньше 0 | `Некорректная посещаемость` |
| TC-12 | 90 | 101 | Негативный, посещаемость больше 100 | `Некорректная посещаемость` |
| TC-13 | `"90"` | 80 | Негативный, неправильный тип `score` | `TypeError` |

Для каждого порогового значения также проверяются соседние значения, перечисленные в разделе «Граничные значения». Для неправильных типов используются строки, `None`, списки, словари и произвольные объекты.

## Стратегия автоматизации

Тесты находятся в `tests/test_student.py` и используют:

- `pytest.mark.parametrize` для повторного запуска одного сценария с разными данными;
- `pytest.raises()` для проверки исключений `TypeError`;
- отдельные понятные тестовые функции для классов эквивалентности, границ и некорректных входных данных.
